## Размышления

**Задание с самого начала было сформулировано неточно, и это оказалось главным.**
Просили «grillme mcp». Проверка показала, что MCP-сервера с таким именем не
существует: ни в реестрах (mcp.so, glama, mcpservers.org), ни в
`modelcontextprotocol/servers`. Все совпадения ведут на `grill-me` — это **скилл**,
а не MCP-сервер. Лежит в `mattpocock/skills`, путь `skills/productivity/grill-me`,
проверено через GitHub API (`/repos/mattpocock/skills/contents/skills/productivity`).

Соблазн был выполнить буквально — найти хоть что-то с похожим названием и
прописать в `.mcp.json`. Отвергнуто: MCP и скилл — разные механизмы (сервер с
инструментами по протоколу против markdown-инструкции для агента), и подмена одного
другим дала бы неработающий конфиг. Поэтому остановился и переспросил — это как раз
случай из «Когда агент обязан остановиться» в AGENTS.md: требование допускает два
прочтения плюс добавляется зависимость, которой в проекте нет.

**Вторая неочевидность — сам скилл почти пустой.** `grill-me/SKILL.md` — семь строк,
и всё тело сводится к `Call the Skill tool with "grilling"`. То есть в одиночку
`grill-me` бесполезен, он лишь входная точка к соседнему скиллу `grilling`. Это
важно для выбора способа установки: любой вариант «выдернуть один скилл» требует
тащить минимум два. Заметил только после того, как прочитал файл целиком —
из описания в реестрах этого не видно, там расписан функционал `grilling`.

**Выбор способа установки.** Рассматривались три:

1. Плагин Claude Code (`claude plugins install mattpocock-skills`) — управляемый
   read-only набор из официального маркетплейса, обновляется сам, репозиторий
   проекта не трогает.
2. `npx skills@latest add mattpocock/skills` — копирует редактируемые файлы скиллов
   в репозиторий, обновления вручную, требует Node.js.
3. Скопировать два `SKILL.md` руками через curl.

Выбран (1). Логика: проблема зависимости `grill-me` → `grilling` решается сама
собой, когда ставится весь набор; править файлы скилла в рамках этой задачи не
нужно, а значит редактируемость из (2) — плата без выгоды. Вариант (3) отвергнут
из-за риска не заметить вспомогательные файлы скилла (`references/`, скрипты),
если они появятся.

Плата за (1) честная и её стоит записать: ставится **глобально, а не в проект**, и
**целиком** — вместе с grill-me приезжают все остальные скиллы набора
(`implement`, `triage`, `code-review`, `tdd` и ещё пара десятков). Отдельно
grill-me не выдернуть. Для учебного репозитория это скорее плюс, но «добавили в
проект» здесь означает «сделали доступным агенту в этом проекте», а не «положили
файл в репозиторий» — в git не попадёт ничего.

**Что показала проверка — и почему хорошо, что я не остановился на «готово».**
Установка прошла без ошибок, `claude plugin list` показал плагин как enabled, файлы
скиллов нашлись на диске. По правилам курса этого мало, поэтому запустил чистую
сессию `claude -p` и спросил, видит ли она скиллы. Ответ: **`grilling: да`,
`grill-me: нет`**.

Сначала выглядело как провал установки. Разбор показал обратное: в
`grill-me/SKILL.md` стоит `disable-model-invocation: true`. Это значит, что скилл
намеренно скрыт от автоматического вызова моделью и остаётся доступен только
человеку — через `/grill-me`. То есть «нет» в списке модели здесь не баг, а
задумка автора: интервью запускает пользователь, а не агент по своему усмотрению.
Соседний `grilling`, который делает всю работу, флага не имеет и модели виден —
что сходится с картиной «grill-me это входная точка для человека».

Отдельно: в README репозитория команда указана как `claude plugins install`
(множественное число), реально работает `claude plugin install`. Мелочь, но если
копировать из README вслепую — получишь ошибку.

Что осталось непроверенным честно: я подтвердил наличие файлов, статус плагина и
видимость `grilling` в чистой сессии, но сам `/grill-me` не запускал — он
разворачивает длинное интервью, и делать это внутри технической сессии смысла нет.
Финальную проверку одним нажатием делает пользователь.

## Использованные инструменты

| Инструмент | Действие | Зачем |
|---|---|---|
| WebSearch | поиск «grillme MCP server» | выяснить, что это вообще такое |
| WebFetch | mcp.so/skills/grill-me | уточнить природу пакета — вернул 403, бесполезен |
| curl + GitHub API | обход `mattpocock/skills` | найти реальный путь скилла и прочитать SKILL.md |
| `claude mcp list` | снимок текущих MCP | убедиться, что grill-me там нет и конфликта не будет |
| `claude plugin install` | установка `mattpocock-skills` | собственно задача |
| `claude plugin list` | проверка статуса | убедиться, что плагин enabled |
| `find` по `~/.claude/plugins` | поиск файлов скиллов | проверить, что grill-me и grilling реально на диске |
| `claude -p` (чистая сессия) | запрос списка скиллов | проверка «со стороны», без истории этого обсуждения |

## Финальный вердикт

**Пункт закрыт, но с поправкой к формулировке задачи.** `grillme mcp` как MCP-сервер
не существует; поставлено то, что под этим именем реально есть — скилл `grill-me`
в составе плагина `mattpocock-skills@1.2.3`, вместе с `grilling`, на котором он
держится.

Сделано: плагин установлен (scope: user), статус enabled, файлы скиллов на диске,
`grilling` виден в чистой сессии.

Осталось: пользователю нажать `/grill-me` в новой сессии — это единственная
проверка, которую я не выполнил намеренно. Если команда не находится, вероятная
причина — сессия стартовала до установки, помогает перезапуск.

Не сломано ничего: существующие MCP-серверы (Google Drive / Gmail / Calendar) не
затронуты, файлы проекта не менялись.

Побочный эффект, о котором стоит помнить: вместе с `grill-me` установился весь
набор Мэтта Покока — около трёх десятков скиллов (`implement`, `triage`, `tdd`,
`code-review` и прочие). Выборочно снять один нельзя; если набор мешает — удаляется
целиком через `claude plugin uninstall mattpocock-skills`.
