# QA-проверка блога AbeloHostRepTechTask

Домашнее задание после занятия 1, **задание 4 (QA)**: «Проверка продукта,
который сделал агент».

Здесь нет разработки. Предмет работы — **проверка** существующего веб-приложения
и доказательства этой проверки: тест-план с ожиданиями, записанными до прогона,
баг-репорты с артефактами, автотест, падающий на реальных дефектах, фикс одного
бага с повторным прогоном и разбор того, где отчёт агента разошёлся с фактом.

---

## Почему выбрана эта тема

В задании прямо сказано, что свой проект предпочтительнее списка из семи тем.
Готовый проект был — PHP-блог, написанный как тестовое задание в апреле 2026
(`github.com/aprelev-developer/AbeloHostRepTechTask`).

Сдать его как основную реализацию нельзя: чек-лист требует «`SPEC.md` написан до
реализации, а не восстановлен после» и сохранённый наивный прогон. Проект
закончен четырьмя месяцами раньше и содержит два коммита — спецификация под него
была бы пересказом кода, а наивного прогона задним числом не бывает.

Зато задание 4 устроено так, что приложение появляется **раньше** тестировщика и
история его создания недоступна. Блог подошёл под это буквально. Предметом
спецификации стала тест-стратегия — и она честно написана до первой проверки.
Разбор этого решения — в `sessions/session-3.md` и `SPEC.md` §16.

## Как запустить

Нужны Docker и Python 3. Больше ничего ставить не нужно: автотест использует
только стандартную библиотеку.

### 1. Поднять объект тестирования

```bash
git clone --branch develop \
  https://github.com/aprelev-developer/AbeloHostRepTechTask.git app-under-test
cd app-under-test
cp .env.example .env

# если порт 3306 на машине занят — скопировать готовый override из этого репозитория
cp ../docker-compose.override.yml .

docker compose build && docker compose up -d
docker compose exec -T php composer install --no-interaction
for f in database/migrations/*.sql; do
  docker compose exec -T mysql mysql -ublog_user -pblog_password blog < "$f"
done
docker compose exec -T php php database/seeders/run.php
docker compose exec -T php sass resources/scss/main.scss public/css/style.css --no-source-map
cd ..
```

### 2. Убедиться, что стенд жив

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/   # ожидается 200
```

### 3. Прогнать автотест контракта

```bash
python3 qa/test_contract.py
```

**Тест обязан упасть.** Четыре проверки из восемнадцати красные — это BUG-001 и
BUG-002, которые не чинились намеренно. Зелёный тест здесь означал бы, что он
ничего не проверяет. Код возврата `1` — ожидаемый.

### 4. Остановить стенд

```bash
cd app-under-test && docker compose down
```

Пароли `blog_user` / `blog_password` — учебные значения из `.env.example` самого
объекта, а не секреты. Реальных ключей и токенов в репозитории нет.

## Что найдено

| # | Дефект | Серьёзность | Чем доказан |
|---|---|---|---|
| BUG-001 | `page` валидируется несогласованно: `0` и `-1` → 400, а `abc`, пустое значение и 20-значное число молча открывают первую страницу | значительная | разбор кодов ответа |
| BUG-002 | Страница за пределами диапазона пишет «в категории нет постов» — при 8 постах в категории; пагинации нет вовсе, выйти из состояния нечем | значительная | скриншот |
| BUG-003 | `HEAD` на любую страницу отдаёт 405; отвечает само приложение (`X-Powered-By: PHP`) | значительная | разбор заголовков ответа |

Одна находка доказана скриншотом, другая — разбором ответа, и в
`qa/test-report.md` объяснено, почему наоборот не вышло бы: ложность фразы
«постов нет» видна только на экране рядом с заголовком категории, а неверный
код на `HEAD` браузер пользователю не показывает вовсе.

**Починен один дефект** — BUG-003, в ветке `qa-fix/BUG-003` локального клона.
Повторный прогон того же тест-плана: было 12 из 18, стало 14 из 18, регрессий
нет (GET отвечает 200, POST по-прежнему 405). В `github.com/aprelev-developer`
не отправлено ничего.

## Что не сделано и что упрощено

Честно и без смягчений.

- **Ширина 360 не проверена.** `resize_window` дважды ответил «Successfully
  resized … to 360x800», но окно не изменилось: скриншот остался 1568 px, вёрстка
  трёхколоночной. Требование курса «две ширины» закрыто наполовину. Имитировать
  360 масштабированием я не стал — это выдало бы за проверку то, чем оно не
  является. Подробности — `qa/discrepancies.md`, D-1.
- **Наивный прогон нашёл два дефекта HIGH, которых нет в моём тест-плане** —
  показ одной категории из нескольких на странице поста и вывод сегодняшней
  даты у всех постов. Обе находки я перепроверил сам и подтвердил. Мой фокус
  («границы параметров») исключил целый класс дефектов — рассогласование двух
  экранов между собой. Разбор — `qa/discrepancies.md` D-2 и
  `naive-run/COMPARISON.md`.
- **Эти два HIGH не подняты в баг-репорты и не покрыты автотестом.** Найдены за
  час до дедлайна; поднимать их в баг-репорты значило бы либо не успеть, либо
  выдать чужую находку за свою. Оставлены как подтверждённые находки в разборе.
- **Два дефекта из трёх не починены** — BUG-001 и BUG-002. По условию задания
  чинится один; остальные остаются как находки.
- **Безопасность, доступность, кросс-браузерность, нагрузка — вне объёма**
  (`SPEC.md` §12). Проверено только экранирование и то, что `sort` не уходит в
  SQL. Утверждать «приложение безопасно» я не могу и не утверждаю.
- **Пагинация не проверена по-настоящему:** при сидовых данных максимум 8 постов
  в категории, и контролы пагинации не появляются ни на одной странице.
  Отличить «пагинация сломана» от «данных меньше, чем размер страницы» чёрным
  ящиком не удалось — зафиксировано как неоднозначность U5 в `SPEC.md` §10.
- **T03 прошла по случайности.** Ожидание «порядок соответствует убыванию
  просмотров» было записано без учёта того, что у всех постов 1 просмотр.
  Проверка сработала только потому, что мои же запросы накрутили счётчик одного
  поста. Ожидание в `SPEC.md` задним числом не переписано (`qa/discrepancies.md`, D-5).
- **`sessions/session-1.md` остался пустым шаблоном.** Работа фактически
  началась с сессии 2, до моего участия. Задним числом не заполнял.
- **Отклонение стенда от оригинала:** `docker-compose.override.yml` снимает
  публикацию порта 3306, потому что на машине занят чужой контейнер. Файлы
  объекта не изменялись.

## Ограничения проверки

- Проверка чёрным ящиком: исходный код объекта читался только для фикса BUG-003.
- Один браузер (Chrome), одна ширина (1440), одна конфигурация окружения.
- Данные — только сидовые: 6 категорий, 25 постов, у всех постов один просмотр
  на старте. Часть граничных случаев на таких данных недостижима.
- `APP_DEBUG=true`, как в `.env.example` объекта. Поведение в продакшен-режиме
  не проверялось.
