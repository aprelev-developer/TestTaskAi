# BUG-004 · Страница поста показывает одну категорию из нескольких — листинг и карточка противоречат друг другу

- **Серьёзность:** значительная
- **Компонент:** `GET /post/{id}`, блок категорий и «Related Posts»
- **Проверка тест-плана:** T05 (ожидание было записано, но зачтено неверно —
  см. «Происхождение находки»)
- **Окружение:** http://localhost:8080, Docker, сид 6 категорий / 25 постов,
  клон на ветке `develop`

## Шаги воспроизведения

1. Открыть `http://localhost:8080/category/design` — убедиться, что в списке
   есть пост «Modern CSS Techniques You Should Know» (`/post/4`)
2. Открыть `http://localhost:8080/category/programming` — убедиться, что тот же
   пост `/post/4` есть и здесь
3. Открыть `http://localhost:8080/post/4`
4. Посмотреть, какие категории объявлены на странице поста

## Ожидаемый результат

Страница поста показывает **все** категории, в листингах которых он
присутствует. Источник: `SPEC.md` §9, T05 — «Заголовок, текст и **категории**
поста отображены» (множественное число), и `SPEC.md` §5, сценарий 3 —
«видит заголовок, текст, **принадлежность к категориям**».

## Фактический результат

```
пост 4 присутствует в листингах: design, programming
на странице /post/4 объявлено:   design
```

Проверено автоматически, `qa/test_contract.py`, проверка T05c:

```
[FAIL] T05c   BUG-004: страница поста показывает все категории,
              в листингах которых он есть
         └─ в листингах ['design', 'programming'], на странице поста ['design']
```

Показывается категория с меньшим идентификатором, то есть первая из связки, а не
выбранная как главная. Следствие: блок «Related Posts» строится по этой одной
категории, поэтому в «похожие» попадают статьи только из неё.

## Доказательство

`qa/evidence/autotest-final-develop.log` — проверка T05c с перечислением обеих
сторон расхождения.

**Чем пойман:** сравнением двух страниц между собой. Ни скриншотом, ни разбором
одной страницы дефект не ловится: каждая страница по отдельности выглядит
совершенно нормально. Дефект существует только в отношении между листингом и
карточкой.

## Почему это дефект

Читатель, пришедший из раздела Programming, открывает статью и видит, что она
относится к Design. Навигация противоречит сама себе, а блок «похожих» уводит не
туда, откуда человек пришёл. Для постов, состоящих в двух категориях (таких в
сиде большинство), одна из категорий фактически перестаёт существовать на уровне
карточки.

## Происхождение находки — записано честно

Этот дефект **нашёл наивный прогон**, а не мой тест-план. Мой прогон зачёл
проверку T05 как пройденную, прочитав собственное ожидание «категории» в
единственном числе (`qa/test-report.md`, исходный вердикт T05 — «✅ прошла,
категория Design»).

Ошибку показал независимый аудит (`qa/audit-findings.md`, A-5). До аудита я
объяснял пропуск структурной причиной — «фокус на входах не позволял увидеть
класс дефектов о рассогласовании экранов». Объяснение оказалось неверным и
удобным: дефект был внутри плана, проверка на него существовала, и я её
неправильно зачёл.
