## Результаты

### T01 · позитив · `/` — главная

- **Ожидалось:** 200, 6 категорий, карточки ведут на существующие `/post/{id}`
- **Факт:** 200. `<title>Blog - Home</title>`. Видны все 6 категорий
  (Business, Design, Lifestyle, Programming, Science, Technology), карточки
  сгруппированы секциями по категориям. Ссылки ведут на существующие посты.
- **Вердикт:** ✅ прошла
- **Доказательство:** `qa/evidence/T01-home-1440.jpg`, `probe-http.log`
- **Примечание:** пост, входящий в две категории, показывается в обеих секциях
  (id=19 встречается дважды). Сначала принял за дубль — при разборе разметки
  оказалось, что это устройство главной, а не дефект.

### T02 · позитив · `/category/programming`

- **Ожидалось:** 200, только посты этой категории, заголовок соответствует слагу
- **Факт:** 200, `<title>Programming</title>`, 8 постов
  `[24, 22, 20, 16, 12, 10, 4, 1]`, заголовок и описание категории на месте
- **Вердикт:** ✅ прошла
- **Доказательство:** `probe-edge.log`, `qa/evidence/T02-category-technology-1440.jpg`

### T03 · позитив · `?sort=views`

- **Ожидалось:** порядок отличается от `sort=date` и соответствует убыванию просмотров
- **Факт:** порядок `[4, 24, 22, 20, 16, 1, 12, 10]` против `[24, 22, 20, 16, 12, 10, 4, 1]`
  при `sort=date`. Пост id=4 поднялся на первое место после того, как счётчик его
  просмотров вырос до 2 — то есть сортировка действительно по просмотрам.
- **Вердикт:** ✅ прошла
- **Оговорка честно:** на сидовых данных у всех постов 1 просмотр, поэтому
  проверка стала возможной только потому, что предыдущие проверки сами
  накрутили счётчик. Это удача, а не заслуга плана: ожидаемый результат в
  `SPEC.md` был сформулирован без учёта того, что данные равны.

### T09 · граница · `?page=2` (страница за диапазоном)

- **Ожидалось:** сообщение объясняет, что **страницы нет**; из состояния есть
  выход к данным
- **Факт:** 200 и текст **«No posts found in this category.»** — при том что в
  категории 8 постов. Элементов пагинации на странице нет вовсе, ссылки на
  первую страницу нет. Единственный выход — «Home» в шапке или правка URL.
- **Вердикт:** ❌ **упала** → BUG-002
- **Доказательство:** `qa/evidence/BUG-002-page2-misleading-empty-1440.jpg`

### T10 · граница · `?page=0`, `?page=-1`, `?page=abc`

- **Ожидалось:** детерминированный ответ, **одинаковая логика для всех трёх**, не 5xx
- **Факт:** логика разная:

  | Вход | Ответ | Сообщение |
  |---|---|---|
  | `page=0` | **400** | Page must be greater than 0 |
  | `page=-1` | **400** | Page must be greater than 0 |
  | `page=abc` | **200** | молча показана страница 1 |
  | `page=1.5` | **200** | молча показана страница 1 |
  | `page=` (пусто) | **200** | молча показана страница 1 |
  | `page=%20` (пробел) | **200** | молча показана страница 1 |
  | `page=99999999999999999999` | **200** | молча показана **страница 1** |

- **Вердикт:** ❌ **упала** → BUG-001
- **Отдельно опасное:** двадцатизначный номер страницы отдаёт не пустую выборку
  и не 400, а первую страницу — то есть значение, переполняющее int, молча
  превращается в «страницу по умолчанию»

### T11 · граница · `?sort=hacked`

- **Ожидалось:** откат к умолчанию либо 400, не 5xx, значение не в SQL
- **Факт:** **400**, «Invalid sort parameter. Allowed: date, views, title».
  Дополнительно проверено `?sort=title'--` → тоже 400, признаков попадания
  значения в SQL нет
- **Вердикт:** ✅ прошла
- **Примечание:** решение строгое (400), тогда как для `page` выбрано мягкое
  (молча по умолчанию) — источник несогласованности из BUG-001

### T12 · смежные риски · вёрстка 360/1440, консоль, экранирование

Проверка составная, поэтому вердикт по частям.

| Часть | Факт | Вердикт |
|---|---|---|
| 1440, главная и категория | вёрстка в три колонки, ничего не перекрывается, горизонтальной прокрутки нет | ✅ |
| консоль | сообщений нет вовсе, включая ошибки и предупреждения | ✅ |
| экранирование | `/category/<script>alert(1)</script>` → 404, скрипт не исполнился и в разметку не попал | ✅ |
| **360** | **не проверено** | ⛔ **заблокирована** |

- **Вердикт:** ⚠️ **частично заблокирована**
- **Почему заблокирована:** `mcp__claude-in-chrome__resize_window` дважды
  ответил «Successfully resized window … to 360x800 pixels», но следующий
  скриншот остался шириной 1568 px и вёрстка сохранила три колонки. То есть
  инструмент отчитался об успехе, а изменения не произошло. Подделывать ширину
  масштабированием или объявлять проверку пройденной по виду 1440 я не стал.
- **Последствие:** заявленное курсом требование «две ширины» закрыто наполовину.
  Записано в `qa/discrepancies.md` (D-1) и в README как несделанное.

## Как распределены доказательства

Требование курса — одну находку доказать скриншотом, другую разбором разметки.

- **BUG-002 доказан скриншотом** (`BUG-002-page2-misleading-empty-1440.jpg`):
  суть дефекта в том, **что читатель видит на экране** — фраза «постов в
  категории нет» на странице категории с восемью постами. Разбором разметки это
  доказывается хуже: в HTML это просто строка текста, её вводящий в
  заблуждение смысл виден только рядом с заголовком категории и пустой сеткой.
- **BUG-003 доказан разбором ответа** (`probe-edge.log`): дефект в коде ответа
  на метод HEAD. Скриншотом он не ловится в принципе — браузер не показывает
  HEAD-запрос пользователю, на экране всё выглядит нормально.
- **BUG-001 доказан таблицей кодов ответа** (`probe-edge.log`): дефект — в
  **несогласованности** семи входов между собой. Один скриншот показывает один
  вход и несогласованности не выявляет.
