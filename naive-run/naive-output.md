## Что за приложение

PHP 8.3 / nginx блог: главная, 6 категорий, 25 постов, сортировка (date/views/title), счётчик просмотров, «Related Posts». Пользовательского ввода (поиск, комментарии, авторизация) нет.

## Баги

### 1. На странице поста показывается только одна категория из нескольких — HIGH

11 из 25 постов принадлежат двум категориям (это видно по листингам), но страница поста выводит ровно одну:

| Пост | Реальные категории | Показано |
|---|---|---|
| 1 «Getting Started with PHP 8.3» | programming, technology | **Technology** |
| 4 «Modern CSS Techniques» | design, programming | **Design** |
| 5 «Building Scalable Web Applications» | business, technology | **Technology** |
| 19 «Remote Team Management» | business, lifestyle | **Business** |

Всего затронуты посты 1, 3, 4, 5, 10, 11, 16, 19, 22, 24, 25.

Выбирается категория с наименьшим id (проверил — правило согласовано для всех 11 пар), т.е. просто первая из связки, а не «главная». Отсюда следствие: **блок «Related Posts» строится по этой одной категории**. Пост 5, который на главной стоит в разделе Business, открывается как статья Technology и получает в «похожие» только technology-посты (16, 24, 25). Листинг и деталка противоречат друг другу.

### 2. У всех постов одна и та же дата — сегодняшняя — HIGH

Все 25 постов показывают `August 17, 2026` — это дата деплоя (`Last-Modified` на style.css: `Mon, 17 Aug 2026 13:16:50 GMT`).

При этом в данных даты **разные**: `?sort=date` даёт стабильный порядок, который не совпадает ни с id, ни с title, ни с views — например для design `18, 22, 4, 7, 13` (тогда как по id было бы `22, 18, 13, 7, 4`). Значит `ORDER BY published_at` реально работает, а шаблон выводит не `published_at`, а текущую дату.

Побочный эффект: для пользователя «Sort by: Date» выглядит сломанным — порядок карточек меняется, а даты на всех карточках одинаковые.

Проверка: открыть сайт завтра. Если все посты покажут `August 18, 2026` — подтверждено.

### 3. Пагинация не работает и выдаёт ложное сообщение — MEDIUM

```
curl -s "http://localhost:8080/category/programming?page=2"
→ HTTP 200, «No posts found in this category.»
```

В категории 8 постов, сообщение неверное. При этом:
- разметка `.pagination` **не рендерится ни на одной странице**, хотя в `style.css` есть `.pagination`, `.pagination__link`, `.pagination__link--active`, а `app.js` навешивает обработчик на `.pagination__link` — фича мёртвая;
- на страницу 2 нельзя перейти из UI и нельзя вернуться назад — только правкой URL;
- limit на первой странице не применяется: все 8 постов выводятся сразу.

### 4. HEAD возвращает 405 — MEDIUM

```
HEAD /            → 405
HEAD /post/7      → 405
OPTIONS /post/7   → 405
```

По RFC 9110 HEAD обязателен там, где поддерживается GET. Ломает краулеры, link-checker'ы и внешний мониторинг (health-check по HEAD будет считать сайт лежащим). Плюс во всех 405-ответах **отсутствует обязательный заголовок `Allow`**.

### 5. «1 views» — множественное число не согласовано — LOW

Из первого снимка главной (до каких-либо визитов):
```
16 × <span>0 views</span>
 2 × <span>1 views</span>
```
Слово `views` подставляется безусловно, нужно `1 view`.

### 6. Счётчик просмотров накручивается тривиально — LOW

Каждый GET страницы поста даёт +1, без дедупликации по сессии/IP/времени. 100 запросов = +100 просмотров (проверено). Обычный F5 инфлирует счётчик, а «Sort by Views» из-за этого легко исказить.

Справедливости ради: инкремент **атомарный** — при 100 параллельных запросах в 25 потоков потерянных обновлений нет (`delta=100`), листинги счётчик не накручивают, HEAD/POST — тоже.

### 7. Несогласованная валидация параметров — LOW

| Запрос | Ответ |
|---|---|
| `/post/0` | 400 «Invalid post ID» |
| `/post/-1`, `/post/abc` | 404 «Post not found» ← должно быть 400 |
| `?sort=bogus`, `?sort=` (пусто) | **400, страница целиком не открывается** |
| `?page=abc`, `?page=1.5` | 200, молча откат на стр. 1 |
| `?page=0`, `?page=-1` | 400 |

Два параметра ведут себя противоположно: некорректный `page` игнорируется, некорректный `sort` роняет страницу в ошибку. Для параметра отображения корректнее откат на значение по умолчанию. Отдельно неприятно, что `?sort=` (пустое значение — типичный результат отправки формы) даёт 400.

### 8. Дубли URL и отсутствие редиректов — LOW

- `/post/01`, `/post/001`, `/post/1%20` → 200 с тем же постом, `rel="canonical"` нет → дублирующийся контент;
- `/post/1/`, `/category/business/` (слеш в конце) → **404** вместо 301;
- `/category/Business` → 404, слаги регистрозависимы;
- `/config.php`, `/info.php` → голый текст `File not found.` вместо стилизованной 404 (остальные 404 отдаются нормальным шаблоном).

### 9. SEO / доступность — LOW

Нет `meta description`, `canonical`, Open Graph. `<time>` без атрибута `datetime` (машинно-нечитаемая дата). На странице категории иерархия заголовков прыгает h1 → h3. Все `<img>` без `width`/`height` (layout shift) и без `loading="lazy"`; 18 изображений на главной грузятся сразу.

### 10. Заголовки безопасности и производительность — LOW

Отсутствуют `Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`. Раскрываются версии: `X-Powered-By: PHP/8.3.33`, `Server: nginx/1.29.6`. HTML отдаётся **без gzip** (главная 14.7 КБ) и без `Cache-Control` — при этом на CSS кэширование настроено корректно.

### 11. Внешняя зависимость от picsum.photos — LOW

Все картинки хотлинкятся с `picsum.photos`, локального фолбэка нет. Без интернета/при блокировке сервиса все изображения на сайте битые.

## Что проверено и работает

- **SQL-инъекции** — 15 payload'ов в `id`, слаг и `sort` (кавычки, `OR 1=1`, `UNION SELECT`, `DROP TABLE`, комментарии): корректные 404/400, ни одной утечки `SQLSTATE`/`PDO`/stack trace. `sort` явно валидируется по белому списку.
- **XSS** — рефлексии в path и query нет.
- **Path traversal** — `/..`, `%2e%2e%2f`, `/post/1%2F..%2F..%2Fetc%2Fpasswd` заблокированы.
- **Утечки ошибок** — display_errors выключен, стандартные error-страницы 400/404 без деталей.
- **Сортировка** `views` (по убыванию) и `title` (по возрастанию) — корректны, проверено на различающихся значениях.
- **Related Posts** — всегда 3 шт., сам пост исключён, дублей нет, все связаны общей категорией.
- **HTML** — валидная вложенность, незакрытых тегов и дублирующихся `id` нет; `lang`, `alt` у всех картинок присутствуют.
- **Устойчивость** — 5000-символьные id/слаги, 500 query-параметров, 6 КБ заголовок, подмена `Host` обрабатываются без ошибок.
- **Производительность** — 3–7 мс на страницу, признаков N+1 нет.
